# Academic persistence notes

The first migration owns only EduPay Académico academic data. Every relationship
foreign key includes `tenant_id`, so PostgreSQL rejects cross-tenant joins even
when internal UUIDs are known. The canonical tenant identifier is supplied by
the trusted Identity context and is not generated by this schema.

Prisma 7 cannot express PostgreSQL partial unique indexes or table check
constraints in `schema.prisma`. The migration therefore contains reviewed SQL
for coherent academic-year dates, non-negative CourseSubject ordering, and one
active CourseSubject/enrollment/teacher assignment per relationship key.
Inactive and archived rows remain available as academic history, and a later
active relationship can be created without rewriting that history.
